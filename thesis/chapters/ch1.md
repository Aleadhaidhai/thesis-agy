# 第1章 绪论

## 1.1 研究背景与意义

### 1.1.1 研究背景

随着企业数字化转型的深入，即时通讯（Instant Messaging，IM）工具已经从单纯的沟通软件演变为企业协同办公的核心载体。研发团队在群聊中讨论技术方案、排查线上故障，产品团队在群聊中评审需求、同步排期，职能部门则通过全员群发布制度与通知。与邮件、文档等传统知识载体相比，IM 中的信息具有产生频率高、实时性强、参与者广泛等特点，大量与业务决策、问题处理、经验总结相关的知识最先、甚至仅在 IM 中出现。组织知识创造理论指出，组织知识需要经历隐性知识与显性知识之间的转化才能沉淀为组织资产[@A1]；企业社交媒体研究也表明，IM 消息天然具备“可见性”和“持久性”，使得聊天记录本身成为可被挖掘利用的知识资产[@A4]。

然而，IM 中的知识难以被有效复用。一方面，群聊消息高度碎片化：一次完整的技术讨论往往被拆分为数十条短消息，并与其他话题的消息交织在一起，单条消息脱离上下文后几乎不具备可理解性。另一方面，IM 中的知识呈现明显的多模态特征：报错信息常以截图形式发送，复盘报告、接口规范以 PDF 或 Word 附件分享，压测数据以 Excel 表格传递，值班交接甚至通过语音完成。传统的企业搜索系统多基于关键词匹配，只能检索消息文本，对截图中的错误码、文档中的条款、语音中的结论几乎无能为力[@A3]。员工在面对“上次支付网关故障的根因是什么”“现在的发布窗口是什么时候”这类问题时，往往只能翻阅大量历史消息或反复询问同事，造成显著的沟通成本与知识流失，即所谓的“聊天即遗忘”现象。

近年来，以 GPT 系列[@B2][@B3]、LLaMA[@B4]、Qwen[@B5][@B6] 为代表的大语言模型（Large Language Model，LLM）在语言理解与生成方面取得突破，检索增强生成（Retrieval-Augmented Generation，RAG）技术[@C1]通过“先检索、后生成”的方式，将外部知识注入大模型的生成过程，有效缓解了大模型的知识时效性不足与幻觉问题[@H4]，成为构建企业知识问答系统的主流范式[@C4]。与此同时，视觉语言模型[@E5][@E6]、语音识别模型[@E16][@E17] 与文档解析技术[@E14] 的成熟，为多模态内容的统一理解提供了技术基础；以 ReAct[@F1] 为代表的大模型智能体（Agent）技术，则使系统能够自主规划检索步骤、调用工具并对结果进行反思[@F3][@C12]。这些技术进展为构建面向企业 IM 的智能知识检索系统提供了可能。

### 1.1.2 研究意义

将 RAG 与 Agent 技术应用于企业 IM 场景并非简单的技术迁移，该场景具有以下特殊挑战：

（1）**知识载体非结构化且话题交织。** 通用 RAG 系统通常面向结构完整的文档，按固定长度切分文本块即可获得语义相对完整的检索单元；而群聊消息流中多个话题交替出现，按时间窗口或消息条数机械切分，会把不同话题的消息混入同一检索单元，或把同一话题拆散到多个单元中，直接影响检索与生成质量。

（2）**多模态知识分散。** 截图、文档、表格、语音等附件中的关键信息只有经过解析才能被检索，而附件一旦脱离发送时的会话语境，其语义往往残缺，例如一张报错截图只有结合“刚才用户中心又报错了”的上下文才能被正确理解和召回。

（3）**权限边界严格。** 企业 IM 中的群聊具有明确的成员边界，不同员工可访问的信息范围不同。知识检索系统若不能在检索阶段严格执行访问控制，就可能把管理层群聊中的融资、薪酬等敏感信息泄露给无权人员[@I2][@I3]，这在企业应用中是不可接受的。

（4）**问题复杂且对可信度要求高。** 员工的提问常常口语化、省略上下文，部分问题需要组合多条信息才能回答；企业知识还存在“新结论覆盖旧结论”的时效性问题。系统必须给出可追溯来源的回答，以便员工核实。

（5）**数据安全与私有化部署要求。** 企业 IM 数据通常属于核心机密，难以上传到公有云大模型服务，系统需要在本地或企业内网完成全部模型推理。

因此，研究并实现一套面向企业 IM 的多模态知识检索 Agent 系统，具有明确的理论与应用价值。在理论上，本文围绕 IM 会话的知识单元构建、权限感知的混合检索和基于 Agent 的检索规划三个问题提出相应方法，丰富了 RAG 技术在非结构化对话数据上的应用研究；在应用上，系统能够把沉睡在群聊、截图、文档和语音中的知识转化为可检索、可问答、可溯源的组织知识，降低员工获取信息的成本，提升新人融入与跨团队协作效率，同时满足企业对数据安全的要求。

## 1.2 国内外研究现状

### 1.2.1 企业知识管理与企业搜索

企业知识管理系统的核心过程可以概括为知识的创造、存储与检索、转移和应用[@A2]。早期的企业搜索研究指出，与互联网搜索相比，企业搜索面临数据源异构、文档缺乏链接结构、需要按用户权限进行“安全裁剪”以及评测困难等独特挑战[@A3]。随着企业社交媒体与 IM 的普及，研究者开始关注从协作平台中挖掘知识。Chatterjee 等人发布了软件开发相关的 Slack 群聊数据集，并对会话进行了解缠标注，表明开发者 IM 中蕴含大量可复用的问答知识[@A5]。工业界方面，NVIDIA 总结了构建企业级 RAG 聊天机器人的经验，强调内容新鲜度、文档级访问控制、评测与安全护栏等工程问题[@A6]。总体来看，现有企业知识管理研究多聚焦于文档类知识库，针对 IM 会话这种非结构化、多模态、强权限数据的系统性研究仍较为缺乏。

### 1.2.2 检索增强生成技术

Lewis 等人首次提出 RAG 框架，将稠密检索器与生成模型联合用于知识密集型任务[@C1]；REALM 则在预训练阶段即引入检索[@C2]。稠密段落检索（DPR）采用双塔编码器学习查询与文档的语义向量[@C3]，成为 RAG 检索端的基础技术。Gao 等人将 RAG 的发展归纳为朴素 RAG（Naive RAG）、高级 RAG（Advanced RAG）和模块化 RAG（Modular RAG）三个阶段[@C4]，国内学者也对 RAG 的检索、增强和生成各环节进行了系统综述[@C5]。

在检索端优化方面，HyDE 通过让大模型先生成假设性答案再检索，提高零样本稠密检索效果[@C8]；Rewrite-Retrieve-Read 框架通过查询改写提升检索质量[@G5]；RAPTOR 采用递归聚类与摘要构建树状索引，支持多粒度检索[@C9]；GraphRAG 借助知识图谱与社区摘要回答全局性问题[@C10]。在生成端可靠性方面，Self-RAG 通过反思标记让模型自主判断是否需要检索以及检索结果是否支撑生成[@C6]；CRAG 引入轻量级检索评估器，在检索质量不佳时触发纠正动作[@C7]；Adaptive-RAG 根据问题复杂度在不检索、单步检索和多步检索之间自适应选择[@C11]。此外，研究发现大模型对长上下文中间位置的信息利用不足[@C13]，说明重排与证据精选对生成质量至关重要。Gao 等人提出的 ALCE 基准则系统评估了大模型生成带引用文本的能力[@H5]。

### 1.2.3 多模态信息检索

多模态检索的代表性工作是 CLIP，它通过大规模图文对比学习将图像与文本映射到同一语义空间[@E1]，Chinese-CLIP 将其扩展到中文场景[@E2]。BLIP-2[@E3]、LLaVA[@E4] 以及 Qwen2-VL[@E5]、Qwen2.5-VL[@E6] 等视觉语言模型则具备细粒度的图像理解与文字识别能力。在文档检索方面，传统流程依赖 OCR[@E13] 和版面分析[@E12][@E14] 将文档转为文本；ColPali 提出直接对页面图像进行多向量编码检索，避免解析损失，并发布了 ViDoRe 评测基准[@E7]。VisRAG[@E8] 和 M3DocRAG[@E9] 进一步把视觉检索与视觉语言模型生成结合，构建多模态 RAG 流程。Abootorabi 等人对多模态 RAG 进行了系统综述[@E10]。语音方面，Whisper[@E15] 与 Paraformer[@E16] 等模型显著提升了语音识别的准确率与效率，FunASR 提供了语音端点检测、识别与标点恢复的完整工具链[@E17]。

上述工作大多针对单一类型的多模态数据（如文档页面或自然图像），而企业 IM 中截图、文档、表格、语音与对话文本混合出现，如何在统一的知识表示下兼顾不同模态的检索需求，并保留多模态内容与会话上下文之间的关联，仍有待研究。

### 1.2.4 大语言模型智能体

思维链提示[@F4] 揭示了大模型的多步推理能力。ReAct 将推理与行动交替进行，使模型能够在“思考—行动—观察”的循环中调用外部工具[@F1]；Toolformer 让模型自监督地学习调用 API[@F2]；ToolLLM 将工具学习扩展到上万个真实 API[@F6]；Reflexion 通过语言形式的自我反思改进后续决策[@F3]。Wang 等人从画像、记忆、规划和行动四个模块总结了基于大模型的自主智能体框架[@F5]。在检索与智能体结合方面，Agentic RAG 将检索作为智能体可调用的工具，由智能体动态决定检索策略[@C12]；Search-o1 在推理过程中按需触发检索[@F7]，Search-R1 则通过强化学习训练模型进行多轮检索推理[@F8]，DeepSeek-R1 等推理模型的出现也进一步增强了智能体的规划能力[@B7]。然而，现有检索型智能体多以开放域问答为评测场景，很少考虑企业场景中的权限约束、时效冲突与可溯源要求。

### 1.2.5 会话解缠与话题切分

会话解缠（Conversation Disentanglement）旨在把交织的多人聊天流拆分为独立的对话线程。Elsner 和 Charniak 构建了首个 IRC 会话解缠语料，并提出基于相关性分类与图划分的方法[@G1]；Kummerfeld 等人发布了大规模 Ubuntu IRC 回复关系标注语料，成为该领域的主流基准[@G2]。对话话题切分方面，Xing 和 Carenini 利用语句对连贯性打分实现无监督话题切分[@G3]。另外，CANARD 数据集研究了多轮对话中的问题改写[@G4]，为对话式检索的查询理解提供了参考。这些研究多作为独立的自然语言处理任务进行评测，尚未与面向检索的知识单元构建结合。

### 1.2.6 研究现状总结

综上所述，RAG、多模态理解和智能体技术均已取得长足进展，但将其应用于企业 IM 知识检索仍存在以下不足：

（1）现有 RAG 系统的文本分块方法面向结构化文档设计，缺乏针对 IM 消息流的话题感知切分与多模态知识单元构建方法；

（2）现有混合检索方案较少同时兼顾文本语义、精确词项和视觉内容三类检索需求，且普遍忽视企业场景下的权限过滤，存在越权泄露风险；

（3）现有检索型智能体缺乏针对企业知识特点（口语化提问、多跳问题、时效冲突、可溯源要求）的规划、反思与引用校验机制；

（4）面向企业私有数据的系统多依赖公有云大模型服务，难以满足数据不出域的安全要求。

## 1.3 本文主要研究内容

针对上述问题，本文设计并实现了一套面向企业即时通讯的多模态知识检索 Agent 系统。主要研究内容如下：

（1）**面向 IM 会话的多模态知识单元构建方法。** 提出融合语义相似度、回复/提及结构关系与时间衰减的在线话题切分方法，将交织的群聊消息流解缠为话题；采用“OCR 精确文本 + 视觉语言模型语义描述”表示图片，结合语音识别、文档版面解析和表格行级序列化，将各类附件统一转写为文本；在此基础上构建会话单元与附件单元两类多模态知识单元（Multimodal Knowledge Unit，MKU），并通过话题摘要增强与附件上下文注入提升可检索性。

（2）**权限感知的多路混合检索方法。** 设计稠密语义、稀疏词项（BGE-M3 词汇权重与 BM25）、视觉跨模态三路召回，采用加权倒数排名融合（RRF）合并结果，再经交叉编码器重排与时效衰减得到最终排序；将基于会话成员关系的访问控制列表（ACL）作为标量过滤条件下推到向量检索内部，实现“先过滤后排序”，并在结果返回前进行二次校验。

（3）**基于 Agent 的检索规划与可溯源问答方法。** 基于状态图构建检索智能体，包含查询理解（指代消解、意图与约束识别、子问题拆分）、检索、充分性反思、引用约束生成与引用校验等节点，使系统能够自主决定改写重检或扩展上下文，并输出逐句标注来源、可跳转到原始消息的回答。

（4）**系统设计、实现与评测。** 设计 IM 适配器抽象接口，使系统与具体 IM 平台解耦；基于开源模型实现全部组件的私有化部署，在无 GPU 的个人计算机上即可运行；由于企业真实数据保密，本文构建了模拟企业 IM 数据集 SimEIM，包含文本、截图、文档、表格和语音多种模态及金标准话题与问答标注，并在该数据集上开展话题切分、检索和端到端问答的对比与消融实验，同时进行系统功能与性能测试。

## 1.4 论文组织结构

本文共分为八章，各章内容安排如下：

第1章为绪论，介绍研究背景与意义，综述企业知识管理、检索增强生成、多模态检索、大模型智能体以及会话解缠等方向的国内外研究现状，提出本文的主要研究内容。

第2章为相关技术基础，介绍大语言模型、信息检索、多模态内容处理、智能体以及向量数据库等相关技术，为后续方案设计提供技术选型依据。

第3章为系统需求分析，从业务场景出发，分析系统的功能需求与非功能需求，给出系统用例模型。

第4章为关键技术方案设计，详细阐述面向 IM 会话的多模态知识单元构建、权限感知的多路混合检索以及基于 Agent 的检索规划与可溯源问答三项关键技术。

第5章为系统总体设计，包括系统架构、功能模块、数据库、接口以及部署架构设计。

第6章为系统详细实现，介绍开发环境与各模块的具体实现，并给出系统运行界面。

第7章为系统测试与实验评估，介绍 SimEIM 数据集的构建方法，开展话题切分、检索与问答实验以及系统功能和性能测试，并对结果进行分析。

第8章为总结与展望，总结全文工作与创新点，分析不足并展望后续研究方向。
