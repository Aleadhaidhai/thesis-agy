# 第2章 相关技术基础

本章介绍系统涉及的关键技术，包括大语言模型、信息检索与重排序、多模态内容处理、大模型智能体以及向量数据库，并结合企业 IM 场景的需求说明各项技术的选型依据。

## 2.1 大语言模型

### 2.1.1 Transformer 与大语言模型

Transformer 是当前大语言模型的基础架构[@B1]，其核心是缩放点积注意力机制：

$$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^{\mathrm{T}}}{\sqrt{d_k}}\right)V \tag{2.1}$$

式中，$Q$、$K$、$V$ 分别为查询、键、值矩阵，$d_k$ 为键向量维度。多头注意力把输入投影到多个子空间并行计算注意力，使模型能够同时捕获不同类型的依赖关系。

GPT-3 证明了在海量语料上预训练的自回归语言模型具备上下文学习能力，只需在提示中给出少量示例即可完成新任务[@B2]。InstructGPT 通过指令微调与基于人类反馈的强化学习（RLHF），使模型输出更符合人类意图[@B3]。LLaMA 等开源基座模型的发布[@B4]，使企业能够在本地部署和定制大模型。

### 2.1.2 Qwen 系列模型

Qwen2.5 系列模型在 18 万亿词元的语料上预训练，提供 0.5B 至 72B 多种参数规模，在中文理解、指令遵循和结构化输出方面表现优异[@B5]。Qwen3 进一步把“思考模式”与“非思考模式”统一到同一模型中：在需要复杂推理时启用思考模式输出推理过程，在简单任务中关闭思考以降低延迟[@B6]。这一特性与本系统的需求高度契合：查询理解、充分性判断等结构化抽取任务可关闭思考以保证响应速度，而复杂问题的推理则可按需开启。DeepSeek-R1 等推理模型通过强化学习激发了长链推理能力[@B7]，为智能体的规划能力提供了基础。

综合中文能力、开源许可、结构化输出能力和本地推理开销，本系统选用 Qwen3-8B（4 比特量化）作为默认生成模型，并通过 OpenAI 兼容接口调用，在开发环境中使用 Ollama 推理，在生产环境中可无缝切换为 vLLM[@I4] 等高吞吐推理框架。

## 2.2 信息检索技术

### 2.2.1 稀疏检索与 BM25

稀疏检索把文本表示为高维稀疏的词项权重向量，其代表算法 BM25 基于概率相关性框架[@D1]。对于查询 $q$ 和文档 $d$，BM25 得分为：

$$\mathrm{BM25}(q,d)=\sum_{t\in q}\mathrm{IDF}(t)\cdot\frac{f(t,d)\,(k_1+1)}{f(t,d)+k_1\left(1-b+b\,\frac{|d|}{\mathrm{avgdl}}\right)} \tag{2.2}$$

式中，$f(t,d)$ 为词项 $t$ 在文档 $d$ 中的词频，$|d|$ 为文档长度，$\mathrm{avgdl}$ 为平均文档长度，$k_1$ 和 $b$ 为调节参数。BM25 对错误码、版本号、IP 地址、人名等精确词项具有很强的匹配能力，这类词项在企业 IM 中十分常见，而稠密向量模型往往难以准确区分。中文文本需要先分词，本系统采用 jieba 的搜索引擎模式分词。

### 2.2.2 稠密检索

稠密检索使用神经网络编码器把查询和文档映射为低维稠密向量，以向量相似度（通常为余弦相似度或内积）衡量相关性：

$$s(q,d)=\frac{\boldsymbol{e}_q\cdot\boldsymbol{e}_d}{\|\boldsymbol{e}_q\|\,\|\boldsymbol{e}_d\|} \tag{2.3}$$

DPR 采用双塔 BERT 编码器并通过对比学习训练[@C3]；Contriever 提出无监督的对比学习检索器[@D9]；E5 利用大规模弱监督数据进行对比预训练[@D10]。ColBERT 采用“后期交互”方式，为每个词元保留向量并计算最大相似度之和，兼顾效果与效率[@D2]。C-Pack 发布了中文文本嵌入评测基准 C-MTEB 与 BGE 系列模型[@D4]。

BGE-M3 是一个同时支持多语言、多功能、多粒度的嵌入模型[@D3]：一次前向计算即可得到稠密向量（[CLS] 隐状态）、稀疏词汇权重（每个词元的隐状态经线性层与 ReLU 得到权重）以及多向量表示，最大支持 8192 词元输入。本系统选用 BGE-M3 同时提供稠密与稀疏两路检索信号，避免部署多个模型带来的资源开销。

### 2.2.3 结果融合与重排序

多路召回的结果需要合并为统一排序。不同检索通路的分数分布差异很大（如 BM25 分数无上界、余弦相似度位于 $[-1,1]$），直接加权求和需要复杂的归一化。倒数排名融合（Reciprocal Rank Fusion，RRF）只利用各通路的排名信息[@D5]：

$$\mathrm{RRF}(d)=\sum_{r\in R}\frac{1}{k+\mathrm{rank}_r(d)} \tag{2.4}$$

式中，$R$ 为检索通路集合，$\mathrm{rank}_r(d)$ 为文档 $d$ 在通路 $r$ 中的排名，$k$ 为平滑常数（通常取 60）。RRF 简单、稳健，无需训练即可取得良好效果。

双塔模型为了检索效率，查询与文档分别编码，交互不足。交叉编码器（Cross-Encoder）把查询与文档拼接后输入同一 Transformer，通过完整的注意力交互输出相关性分数，精度更高但计算量大，因此通常用于对少量候选进行重排序[@D6]。本系统采用 bge-reranker-v2-m3 作为重排模型。

## 2.3 多模态内容处理技术

### 2.3.1 光学字符识别

光学字符识别（OCR）用于从图像中提取文字。PP-OCR 将 OCR 分解为文本检测、方向分类和文本识别三个阶段，以超轻量模型实现了高精度的中英文识别[@E13]。RapidOCR 将 PP-OCR 模型转换为 ONNX 格式，可在 CPU 上高效运行，本系统采用其识别截图中的错误码、配置项等精确文字。

### 2.3.2 视觉语言模型与跨模态检索

CLIP 通过 4 亿图文对的对比学习训练图像编码器与文本编码器，使图像与文本在同一向量空间中对齐，从而支持以文搜图[@E1]。Chinese-CLIP 在约 2 亿中文图文对上训练，适用于中文跨模态检索[@E2]。

视觉语言模型（Vision-Language Model，VLM）把视觉编码器与大语言模型连接起来。BLIP-2 采用轻量的 Q-Former 桥接冻结的视觉编码器与语言模型[@E3]；LLaVA 提出视觉指令微调[@E4]；Qwen2-VL 支持任意分辨率输入，并采用多模态旋转位置编码[@E5]；Qwen2.5-VL 进一步增强了文档解析、图表理解与文字识别能力[@E6]。VLM 能够理解截图的类型与语义（例如“这是一张监控图表，5xx 错误率在 02:10 达到峰值”），弥补 OCR 只识别文字、不理解版面和图表的不足。

在文档检索方面，ColPali 直接把文档页面图像编码为多向量进行检索[@E7]，VisRAG[@E8] 与 M3DocRAG[@E9] 构建了基于视觉检索的多模态 RAG 流程。这类方法效果好，但对 GPU 算力要求高。考虑到本系统需要在无 GPU 环境下运行，本文采用“解析转写为主、视觉向量为辅”的策略：截图与文档页面经 OCR/VLM 转写后进入文本检索通路，同时以 Chinese-CLIP 视觉向量作为补充通路。

### 2.3.3 文档解析

PDF、Word、PPT 等文档包含标题层级、表格、图片等结构信息。LayoutLMv3 通过统一的文本与图像掩码预训练实现版面理解[@E12]；MinerU 提供了把 PDF 精确转换为 Markdown 的开源方案，支持公式与表格识别[@E14]。对于带文本层的电子文档，直接抽取文本层即可获得准确文字；对于扫描件，则需要渲染为图像后进行 OCR。本系统按文档类型分别处理：PDF 逐页抽取文本层并对文本过少的页面回退到 OCR，Word 按标题层级维护章节路径，PPT 以页为单位抽取标题、文本框与备注。

### 2.3.4 语音识别

语音识别（Automatic Speech Recognition，ASR）把语音转为文字。Whisper 基于 68 万小时弱监督数据训练，具有很强的鲁棒性[@E15]。Paraformer 是一种非自回归的端到端语音识别模型，在保持准确率的同时显著提升了推理速度，在中文场景下表现突出[@E16]。FunASR 工具包集成了语音端点检测（VAD）、Paraformer 识别与标点恢复模型[@E17]。本系统采用 FunASR 的 Paraformer 中文模型处理 IM 中的语音消息，该模型可在 CPU 上实时运行。

## 2.4 大模型智能体技术

大模型智能体以大语言模型为“大脑”，通过规划、记忆和工具调用完成复杂任务[@F5]。思维链提示让模型在给出答案前先生成中间推理步骤，显著提升了多步推理能力[@F4]。ReAct 范式将推理（Reasoning）与行动（Acting）交替进行：模型先生成“思考”，再决定调用哪个工具，根据工具返回的“观察”继续推理，直到得出答案[@F1]。Toolformer[@F2] 与 ToolLLM[@F6] 研究了大模型如何学习调用外部工具。Reflexion 让智能体用自然语言总结失败原因并改进后续行为[@F3]。

在检索增强场景中，智能体可以把检索作为工具：根据问题判断是否需要检索、检索什么，并根据检索结果决定是否需要补充检索[@C12]。Self-RAG 训练模型生成反思标记来评估检索必要性和结果的支撑程度[@C6]，CRAG 使用检索评估器判断检索质量并触发纠正动作[@C7]。

本系统采用状态图（State Graph）编排智能体流程。状态图把智能体的执行过程建模为由节点（处理步骤）和边（状态转移条件）构成的有向图，节点之间共享一个状态对象，条件边根据当前状态决定下一步执行的节点。与完全自由的 ReAct 循环相比，状态图在保留“思考—行动—观察—反思”闭环的同时，把流程约束在可控、可观测、可调试的范围内，更适合能力有限的本地小参数模型，也便于在实验中对各节点进行消融。本系统基于开源框架 LangGraph 实现状态图编排。

## 2.5 向量数据库与近似最近邻检索

向量检索需要在海量向量中快速找到与查询最相似的向量。精确的暴力搜索复杂度与数据规模呈线性关系，在大规模场景下难以满足实时性要求，因此通常采用近似最近邻（Approximate Nearest Neighbor，ANN）算法。分层可导航小世界图（HNSW）构建多层近邻图，在高层进行粗粒度跳跃、在底层进行精细搜索，查询复杂度近似为对数级，是目前应用最广泛的 ANN 索引之一[@D7]。倒排文件索引（IVF）先对向量聚类，查询时只搜索最近的若干簇。

Milvus 是专为向量数据管理设计的开源数据库[@D8]，支持稠密向量、稀疏向量等多种向量类型及多种索引，并支持向量检索与标量过滤的混合查询，即在近似最近邻搜索过程中只考虑满足标量条件（如会话 ID、时间范围、访问控制列表）的实体。这一能力是本系统实现“权限过滤下推”的基础。Milvus 提供与集群版接口一致的轻量级本地模式 Milvus Lite，便于在单机上开发与评测，并平滑迁移到生产集群。

## 2.6 本章小结

本章介绍了系统涉及的关键技术：大语言模型方面，选用支持思考模式切换的 Qwen3 作为生成模型；检索方面，介绍了 BM25、稠密检索、BGE-M3、RRF 融合与交叉编码器重排；多模态方面，介绍了 OCR、视觉语言模型、跨模态检索、文档解析和语音识别；智能体方面，介绍了 ReAct、反思机制与状态图编排；存储方面，介绍了 HNSW 索引与 Milvus 向量数据库。这些技术构成了后续方案设计与系统实现的基础。
